- Start eines Videos in der Browserquelle: immer von vorne, beim Einblenden der Quelle (Punkt 53), beim Laden oder Neuladen der Seite durch OBS und beim Einschalten der Ausgabe (E-24). Die Browserquelle spielt unabhängig vom Editor ab, nicht zeitgleich mit ihm.
- Token pro Overlay bleibt (erneut bestätigt 2026-11-03, nach Rückfrage zu Aufwand und Leistung: Vergleich von 43 Zeichen pro Anfrage, nicht messbar gegenüber Zeichnen und Dekodieren). Der Nutzer kopiert pro Overlay einmal die ganze Adresse (Knopf «Kopieren» im Dock «Steuerung») ins Feld «URL» der Browserquelle in OBS.
- Form der Adresse: `http://<Adresse des Studio-PCs>:<Port>/o/<adresse>/<token>/`. Alles, was die Seite nachlädt (Bilder, Videos, Schriften, Verbindung für Änderungen), liegt unter diesem Pfad. Der Kern schreibt die Adresse nie mit Token ins Protokoll (CLAUDE.md, Regel 12).
- Alte Adresse (neue Adresse beim Umbenennen, neuer Token, gelöschtes Overlay): sofort ungültig. Der Server antwortet mit einer leeren, durchsichtigen Seite statt einer Fehlerseite (sonst wäre in OBS ein Kasten mit Text im Stream sichtbar). Der Kern protokolliert «unbekannte Adresse» ohne Token; das Fenster zeigt einen Hinweis, dass eine Browserquelle eine ungültige Adresse benutzt.
- Netzwerk (Angabe des Nutzers 2026-11-03, 19:51): Das Netzwerk zwischen Studio-PC und Streaming-PC ist eingerichtet und funktioniert, beide Systeme sind im Netz. Erhoben und nachgeführt (2026-11-03): `docs/02-umgebung.md` («Netzwerk»), `CLAUDE.md` («Umgebung»), Stand von T-03 bis T-05. Beide PCs per Kabel, Adressen am Router reserviert, Ping 4 von 4. Noch offen für P10: Verhalten bei IPv6 (öffentliche Adressen auf beiden PCs, Sperre des Routers nicht geprüft).
- Prüfung der Browserquelle in zwei Stufen: (1) Claude Code auf dem Studio-PC mit einem Testprogramm auf Basis von Qt WebEngine (schon installiert), Seite über `http://192.168.1.9:8080/…` (echte Netzwerkkarte): Bild mit Durchsichtigkeit, Änderungen ohne Neuladen, Videos, Token, alte Adressen. (2) Handtest des Nutzers in OBS auf dem Streaming-PC (T-04): Browserquelle anlegen, Aussehen gegen den Editor vergleichen, Änderung im Editor in OBS beobachten.
- Bildschirmfoto der Leinwand (Wunsch und Entscheid 2026-11-03, Umsetzung P10-vor): Menüeintrag «Datei → Leinwand als Bild speichern» mit Tastenkürzel (Kürzel wählt der Prompt, ohne Zusammenstoss mit bestehenden). PNG in genau der Auflösung des Overlays, mit Durchsichtigkeit, nur das Overlay (ohne Schachbrett, Auswahlrahmen, Lineale, Zoom). Ablage in `~/Bilder/DoNs Streaming Studio/`, Name `<adresse>_<JJJJ-MM-TT_hh-mm-ss>.png`. Zweck: Vergleich mit dem Bildschirmfoto der Quelle in OBS im Handtest; später nutzbar für P11. Ob OBS beim Bildschirmfoto einer Quelle die Durchsichtigkeit behält: nicht geprüft, Teil des Handtests.
- Adressen des Overlay-Servers: nur IPv4, und zwar die Adresse im Heimnetz (`192.168.1.9`) und `127.0.0.1` (Tests auf dem Studio-PC); nicht IPv6. Grund: Beide PCs haben öffentliche IPv6-Adressen, ob der Router eingehende IPv6-Verbindungen sperrt, ist nicht geprüft.
- Einstellung «Adresse im Heimnetz»: beim ersten Start vom Kern gefüllt mit der IPv4-Adresse der Netzwerkkarte der Standardroute (heute `192.168.1.9` auf `enp3s0`), danach fest. Fehlt die Adresse beim Start (zum Beispiel Kabel nicht eingesteckt), meldet der Kern das deutlich im Fenster, wartet und startet den Server von selbst, sobald die Adresse da ist. Das Dock «Steuerung» zeigt die Adresse zum Kopieren mit dieser Adresse.
- Port je Version: Einsatz (installiert) 8080, Version in Arbeit (`build/`) 8081; beide in der Einstellung änderbar. So kann Claude Code testen, während die echte Browserquelle in OBS weiterläuft. Ergänzt die Tabelle der Orte je Version in `docs/01-festlegungen.md` (Abschnitt «Einsatz»).
- Aufteilung: Die Vorarbeiten (Punkte 67 bis 70 und 72, Bildschirmfoto der Leinwand, Einstellungen Port und «Adresse im Heimnetz», Port je Version) kommen in einen eigenen Auftrag P10-vor vor P10; P10 ist danach nur die Browserquelle. Je eine eigene Claude-Code-Sitzung.
- Einstellungen des Kerns: Datei `kern.ini` im Ordner der Einstellungen der jeweiligen Version (`~/.config/dons-streaming-studio/` bzw. `~/.config/dons-streaming-studio-entwicklung/`); nur der Kern schreibt sie. Ändern im Fenster über «Werkzeuge → Einstellungen …»; der Dialog schickt die Änderung als Nachricht an den Kern. Ein neuer Port gilt sofort (der Server startet neu; der Server selbst kommt mit P10).
